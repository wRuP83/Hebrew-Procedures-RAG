# Hebrew Procedures RAG

אב־טיפוס RAG בעברית לשאלות על נהלי ביטוח סינתטיים, עם הפניות למקורות והערכת איכות בגישת QA. הפרויקט משלב שליפה סמנטית, דירוג מחדש, Gemini, בדיקות דטרמיניסטיות ושופט עם פלט מובנה.

## מטרת הפרויקט

מסמך רלוונטי אינו מבטיח תשובה נכונה. הפרויקט בודק את התהליך כולו, ומבחין בין כשל בשליפה, שינוי כוונה בשכתוב, תשובה שגויה והתראת שווא בכלי הבדיקה.

זהו אב־טיפוס עם חוברת של חברה דמיונית, ללא נתוני לקוחות. אין לראות בו שירות פעיל, ייעוץ רפואי או המלצה ביטוחית.

## ארכיטקטורה

```text
חמישה נהלים סינתטיים → Embeddings רב־לשוניים → Chroma
→ מועמדים עם סינון קהל → Cross-encoder → סף דירוג
→ קונטקסט + Gemini → בדיקות ציטוטים ומספרים + Judge
→ ראיות הרצה והכרעת סקירה נפרדת
```

בשאלות המשך מופעל גם שכתוב לפני השליפה. סירוב קשיח בקוד ותשובת Gemini עם קונטקסט ריק נשמרים בנפרד, כדי לא לייחס למודל התנהגות שבוצעה בתנאי שמירה.

## תוצאות הבסיס

הנתונים מתייחסים להרצה מתועדת מ־9 בנובמבר 2026 על סט בדיקות קטן וקבוע. אין לפרש אותם כמדד דיוק כללי של המערכת.

| מערך | מספר מקרים | פלט אוטומטי | הכרעה לאחר סקירה בסיוע AI |
|---|---:|---|---|
| שאלות בסיס | 19 | 17 PASS_CANDIDATE ושני FAIL | 18 PASS ו־FAIL אחד |
| תסריטי שיחה | 4 | שני PASS_CANDIDATE ושני FAIL | שני PASS ושני FAIL מול חוזה השכתוב |

במערך הבסיס היו 14 שאלות שיש להן תשובה בחוברת וחמש שאין להן תשובה. 13 מהשאלות עם תשובה נענו כראוי, וכל חמש השאלות ללא תשובה סורבו כנדרש.

### ממצאים מרכזיים

- **סף השליפה:** נוהל ביטול דורג ראשון אך סונן, ולכן המערכת סירבה למרות מידע קיים.
- **בודק מספרים:** פסיק אחרי שעה נלכד כחלק ממספר ויצר FAIL שגוי לתשובה תקינה.
- **החלפת נושא:** שאלה על שעות מוקד שירות הפכה לשאלה על מוקד ערעורים שלא נשאל.
- **עמימות:** שאלת המשך קצרה הפרה חוזה של שאלה ללא שינוי, אך אינה מוכיחה כשלעצמה שהמודל המציא כוונה לא סבירה.

הממצאים נשארו גלויים בגרסה זו. התאמת ההצגה אינה תיקון של האלגוריתם, הסף, הפרומפטים או לוגיקת ההערכה.

## הרצה ב־Colab

1. הורד את `notebooks/procedures_rag.ipynb`.
2. ב־Colab בחר **File → Upload notebook**.
3. אפשר למחברת גישה ל־Secret בשם `GEMINI_API_KEY`.
4. הרץ את התאים לפי הסדר; אם נדרש אתחול אחרי ההתקנה, המשך לאחריו לתא הייבוא.
5. הורד את ארכיון התוצאות לפני איפוס הסביבה.

המחברת כוללת את הנתונים ובונה את האינדקס מחדש. כל מריץ משתמש במפתח משלו; הרצה מלאה כוללת 50 קריאות מודל לפני ניסיונות חוזרים, והמכסה והחיוב תלויים בחשבונו.

תוצאות חדשות נכתבות ל־`artifacts/current_run/`, בנפרד מתמונת הבסיס ב־`results/`. אין להעתיק את תמונת הבסיס לתיקיית הריצה כ־checkpoint; הכותרת הציבורית וחתימת גרסת המחברת שונות.

קישור פתיחה ישיר מהמאגר ל־Colab יתווסף לאחר שתהיה כתובת מאגר אמיתית. Colab מאפשר טעינת מחברות מ־GitHub, בעוד GitHub מציג אותן באופן סטטי ([תיעוד Colab](https://research.google.com/colaboratory/faq.html), [תיעוד GitHub](https://docs.github.com/en/repositories/working-with-files/using-files/working-with-non-code-files)).

## טכנולוגיות ותצורה

- **שליפה:** `paraphrase-multilingual-MiniLM-L12-v2` ו־Chroma עם cosine.
- **דירוג:** `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`.
- **יצירה והערכה:** `gemini-3.8-flash`, Interactions API וסכמת Pydantic.
- **פרמטרים:** חמישה מועמדים, עד שלושה נהלים בקונטקסט, ציון גדול ממש מ־‎-2.0.
- **תלויות:** גרסאות ישירות נעולות ב־`requirements.txt`; אין נעילה מלאה לכל תלויות המשנה או גרסאות משקלי המודלים.

התנהגות מודל חי יכולה להשתנות בין הרצות, ויש לבדוק זמינות והרשאות בזמן ההרצה. המימוש נשען על [מדריך Gemini](https://ai.google.dev/gemini-api/docs/quickstart), [הוראות מערכת](https://ai.google.dev/gemini-api/docs/text-generation) ו־[פלט מובנה](https://ai.google.dev/gemini-api/docs/structured-output).

## אימות מקומי

בדיקות מבנה המחברת והראיות, ללא קריאת מודל:

```bash
python -m pip install -r requirements-dev.txt
python tools/validate_release.py
```

בדיקת זרימת המחברת עם שליפה מקומית אמיתית וממשק Gemini ו־Colab מדומה:

```bash
python -m pip install -r requirements.txt -r requirements-dev.txt
python tools/validate_release.py --runtime
```

ייתכן שתידרש הורדת משקלי המודלים. תוצרי הבדיקה המדומים נוצרים בתיקייה זמנית בלבד ואינם נשמרים כתוצאות הפרויקט; פירוט הבדיקות שבוצעו נמצא ב־[דו״ח האימות](reports/validation_report.md).
